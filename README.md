Every coding agent's session starts by re-deriving context: _what does this code do, and why is it like this?_ The code itself answers the first question bit-by-bit and the second not at all. Commit messages describe diffs, not decisions; documentation rots because nothing stops it from rotting. No tool exists to record symbol-level intent - it lives in the programmer's head or in between the conversation turns of the coding agent. Eventually forgotten, lost to time in both cases.

## trie - Meaning and Intent

trie fixes both, in the repo, with the mechanism your code already trusts: version control and a pre-commit gate. It maintains two indexes alongside your source tree and keeps them in-sync in real-time:

1. **The index of meaning** — `triefacts/`: one Markdown file per source file, one section per symbol, describing what each thing does. Generated by an LLM, regenerated only when the underlying source actually changes, cascade-aware (when a function changes, the descriptions of its callers refresh too), and verified at commit time.

2. **The index of intent** — reason why the symbol was changed - recorded _when the change is made_, enforced at commit time. This intent is archived per commit as a file called a _triediff_ that shows up in your PRs. Six months later, `trie read <symbol> --history` tells you the actual history of this specific symbol.

## Quick start

### Prerequisites

- **Python 3.11+** and [`uv`](https://docs.astral.sh/uv/) on PATH
- **[ripgrep](https://github.com/BurntSushi/ripgrep)** (`rg`) on PATH — the `grep` tool's text-match fallback needs it (`brew install ripgrep` / `apt install ripgrep`)
- An Anthropic API key in `ANTHROPIC_API_KEY` (default model: `anthropic/claude-sonnet-4-6`). trie cloud coming soon.
- **Languages supported:** Python, TypeScript/TSX, JavaScript/JSX, Go, Rust, C, Lua
- **LSP:** The environment should have the LSP server corresponding to the language for complete indexing.

```bash
# 1. Installation
uv tool install git+https://github.com/computer-reinvention/trie

# 2. Initialise your project
cd /path/to/your/project
export ANTHROPIC_API_KEY=...
trie init                     # writes trie.toml, scans the symbol graph

# 3. Wire up your coding agent (turn hook + agent docs + tool overrides; MCP optional)
trie setup                    # auto-detects opencode / claude-code / cursor / ...

# 4. Run your first sync
trie sync
```

### `trie setup`

The `trie setup` subcommand augments your preferred coding agent in one idempotent pass. It generates your config, prepares your project for trie and augments your existing coding agent's (Claude Code, OpenCode etc.) behaviour and tools. Here's what it does.

1. **End of turn hook** runs `trie sync --graph-only --after-turn` when the session goes idle, so the graph tracks the agent's edits (no LLM cost).

2. **Tool overrides**
   - the agent's built-in `grep` and `read` become trie-backed
   - `grep` searches the symbol graph (with a ripgrep fallback over source)
   - `read` returns a compact triefact view for files and prose+neighbours for symbols
   - `trace` and the explain/history family are added as new tools.

3. **Agent user manual** `TRIE.md` (the user manual for agents). Automatically appends a pointer to this manual in your `AGENTS.md` / `CLAUDE.md`.

4. **MCP** opt-in via `--with-mcp`; same interface as the CLI. Use it however you want.

5. **Edits** (from `TRIE.md`): all edits are analysed by trie and it blocks until the intent behind every symbol update is recorded. The `trie intent` gate mentioned earlier enforces this deterministically for every session and every commit.

## Configuration

The main config file is `trie.toml`. It is generated automatically during initialization. The config options are sufficiently documented in the file itself.

| Section       | Controls                                                                           |
| ------------- | ---------------------------------------------------------------------------------- |
| `[scope]`     | Include/exclude globs — out-of-scope files are never parsed, never sent to a model |
| `[triefacts]` | Tree root and source root                                                          |
| `[models]`    | Model ids for bootstrap and cascade generation                                     |
| `[cascade]`   | Cascade depth, hub-symbol threshold                                                |
| `[sync]`      | Parallelism, retry policy etc.                                                     |
| `[diff]`      | Digest narrative on/off, file locations, retention                                 |
| `[mcp]`       | Agent-surface tuning (result caps, fuzzy thresholds)                               |
| `[resolver]`  | Type-aware reference resolution (see below)                                        |
| `[debug]`     | Local JSONL telemetry (off by default, never uploaded)                             |

## LSP Setup

Tree-sitter has no type information by itself, so it can't resolve dispatches through a value like (`obj.method()`, `self.helper()`, `this.foo()`), which means the graph trie constructs will be incomplete. Hence, an LSP server is required for complete edge resolution.

Servers are discovered on PATH; when none is installed for a language, that language falls back to tree-sitter-only. These are defaults:

| Language                | Extensions                    | Server                     |
| ----------------------- | ----------------------------- | -------------------------- |
| Python                  | `.py`                         | basedpyright → pyright     |
| TypeScript / JavaScript | `.ts .tsx .js .jsx .mjs .cjs` | typescript-language-server |
| Go                      | `.go`                         | gopls                      |
| Rust                    | `.rs`                         | rust-analyzer              |
| C                       | `.c .h`                       | clangd                     |
| Lua                     | `.lua`                        | lua-language-server        |

```toml
[resolver]
enabled = true                       # master switch (or set TRIE_DISABLE_RESOLVER=1)
# disabled_languages = ["rust", "go"] # force tree-sitter-only per language
# [resolver.servers]                  # override the server command per language
# python = ["basedpyright-langserver", "--stdio"]
```

## How trie works

### The index of meaning: triefacts

One source file maps to one triefact. Given:

```python
# src/slugify.py
def slugify(text: str, max_len: int = 60) -> str:
    """Make a URL-safe slug."""
    text = unicodedata.normalize("NFKD", text).encode("ascii", "ignore").decode()
    text = re.sub(r"[^a-z0-9]+", "-", text.lower()).strip("-")
    return text[:max_len].rstrip("-")
```

`trie sync` writes `triefacts/src/slugify.md`:

```markdown
---
source: src/slugify.py
defines:
  - { kind: function, qualified_name: "src/slugify:slugify", lines: 4-8 }
incoming_refs: 2
---

<!-- trie:section symbol=src/slugify:slugify fingerprint=9f3c… body_fp=8c9b… -->

## `slugify(text: str, max_len: int = 60) -> str`

Normalizes text to a URL-safe slug: strips accents via NFKD, lowercases,
collapses non-alphanumerics to single dashes, trims to `max_len` without
leaving a trailing dash.

<!-- trie:end -->

Anything you write outside the sentinel pairs is yours — notes, warnings,
ADR links. Regeneration preserves it byte-for-byte.
```

### The index of intent: triediffs

Code changes say _what_; they rarely say _why_. trie makes the why a first-class, enforced artifact that records the reason for every symbol's change.

### Enforced workflow

```bash
# 1. Edit source however you like — your editor, your agent, your tools.

# 2. Record why, per touched symbol (one or two sentences):
trie patch create src/slugify:slugify -n "trim trailing dashes; they leaked into generated URLs"

# 3. Commit the notes to the intent ledger (generates nothing):
trie patch apply -N "normalize slug output"

# 4. Sync the triefacts
trie sync
```

Your agent automatically starts following this workflow once you have completed the setup. It uses _hooks_ and _pre-commit guards_ to make it deterministic.

### Pre-commit guard

`trie intent` (in the pre-commit hook) compares the working tree to HEAD **at the normalized-body level** and refuses the commit if any changed symbol lacks a patch note:

```
error: intent gate: 2 of 5 touched symbol(s) have no patch note
  modified src/slugify:slugify
  added    src/slugify:_strip_accents

stage a note per symbol, then re-run:
  trie patch create src/slugify:slugify -n "<why this changed>"
```

Removed symbols are noted with `trie patch create <qname> -n "…" --gone`.

### More about the _triediffs_

At commit time, the hook fuses the recorded notes (stated intent) with the triefact prose deltas (observed effect) into one immutable digest file called a _triediff_. Each coding session has one. It records the reasoning behind every change per symbol which provides missing context about why things are the way they are.

```markdown
## normalize slug output — 2026-07-25 (parent bdadb22)

<short narrative synthesized from the notes and the prose diff>

### Changes

- ~ src/slugify:slugify — "…collapses non-alphanumerics…" → "…trims to max_len
  without leaving a trailing dash."
```

- One file per commit under `triefacts/triediffs/`; `TRIE_DIFF.md` at the repo root is a symlink to the latest.
- The `triediff-comment` GitHub workflow (installed by `trie setup`) comments every digest a PR adds onto the PR itself. _Massively simplifying reviews._

### Querying meaning

The read verbs are the _basis vectors_ for navigation when using trie: without touching the source code, your agents can _find, understand and trace_ any feature or flow. The meaning and purpose are directly stated in plain English for every symbol.

| Tool                               | Returns                                                                        |
| ---------------------------------- | ------------------------------------------------------------------------------ |
| `grep(predicate, rank_by?, limit)` | Matching symbols with one-liners — enough to choose without opening anything   |
| `read(qname \| path, history?)`    | A symbol's prose + caller/callee one-liners, or a file's compact triefact view |
| `trace(qname, direction, depth)`   | Signatures + one-liners across a depth-bounded graph slice                     |

Every response carries one-liners pulled from the prose at sync time, so walking the graph never requires opening a triefact just to decide whether to open it. Agents can trace a whole flow in 5 lines of trie output without reading any source code directly.

### Querying intent

The intent ledger stays in your repo and is queryable by your agents to understand the _why_ during any investigation.

```bash
trie read src/slugify:slugify --history
# …prose, callers, callees…
# history (2)
#   2026-07-25 · ~ trim trailing dashes; they leaked into generated URLs
#     ↳ normalize slug output
```

`--history` works on `trie read` (symbols and whole files), `trie explain-symbol`, and `trie explain-symbol-refs`, and as an opt-in flag on the corresponding agent tools.

## trie as a Wiki

trie also maintains `triefacts/README.md` — a deterministic index that links to every important symbol in your codebase. The most-referenced public symbols (linked, role-tagged, with one-liners) and a per-directory table of contents. Regenerate manually with `trie index`.

### Editing triefacts

Directly editing triefacts is not recommended. Even though it is markdown, trie has a special format that stores hashes, inbound/outbound call counts etc. per symbol. Generated sections belong to trie and will be regenerated if tampered with.

However, the space between generated sections is preserved byte-for-byte and you can put additional notes there using your code editor - it becomes queryable context as well.

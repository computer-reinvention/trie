Documentation rots because nothing stops it from rotting. Commit messages describe diffs, not decisions. Six months later the only record of why the code is the way it is — is the code. trie fixes both, with the same mechanism your code already trusts: version control and a pre-commit gate.

Two indexes, kept honest by construction.

Both live in triefacts/ at the root of your repo. Both are plain Markdown. Both are checked at every commit.

index of meaning

One prose section per symbol.

One source file maps to one triefact. Each function, class, and method gets a section describing what it does and how it connects — regenerated only when the underlying source actually changes, cascade-aware (change a function, its callers' prose refreshes too). Your own notes live in the same files and survive regeneration.

index of intent

One note per changed symbol.

Recorded when the change is made — not reconstructed in a PR description weeks later. A changed symbol with no note blocks the commit. Notes are archived per commit as an immutable digest that shows up in your PRs and answers "why?" forever.

The loop.

Intent is captured at edit time, enforced at commit time, and archived with the commit itself. Every step is a plain command; the gates run offline.

  1. 1

    Edit code normally.

    You — or your agent — change source with the usual tools. trie never generates or edits your code.

  2. 2

    Record intent per symbol.

    A one-line note for each changed symbol: why, not what. Staged locally; nothing leaves your machine. 

    $ trie patch create src/auth:require_auth \
    -n "expired tokens must 401, not 500 — see #241"
  3. 3

    The gate holds the line.

    git commit runs trie gate: prose that drifted from source blocks the commit; a changed symbol with no note blocks the commit. Error output is copy-pasteable fix commands. 

    git commit
  └─ trie gate
      ├─ verify   prose ↔ source, both directions   offline
      ├─ intent   every changed symbol has a note   offline
      └─ diff --write   the commit's digest, staged with it
  4. 4

    The record ships with the commit.

    One immutable digest per commit in triefacts/triediffs/, symlinked from TRIE_DIFF.md. It travels in the same push, shows in the same PR, and merges with the same merge.

  5. 5

    The meaning index stays fresh.

    trie sync regenerates exactly the prose that drifted — plus the callers of what changed. With an agent hook installed, this happens at the end of every turn. 

    $ trie sync        # only what drifted, cascade-aware
$ trie read src/auth:require_auth --history

Six months later: the symbol's current prose, plus every intent note ever recorded against it, in commit order. The story of the code, from the codebase itself.

Everything is in your repo. Nothing else exists.

No hosted index. No sync service. No database server. No dashboard to keep alive. If you can clone the repo, you have all of it.

  • Versioned like code. Branch it, diff it, blame it, revert it. The indexes for a branch describe that branch.
  • Reviewed like code. Prose changes and intent digests appear in the PR diff, next to the code they explain.
  • Merged like code. Markdown merges with git's merge. No custom storage format, no migration server.
  • Gated like tests. trie verify and trie intent are offline checks — they run in a pre-commit hook or any CI runner, no API key needed.
  • Readable with nothing installed. It's Markdown. GitHub renders it. Your editor renders it. cat renders it.
  • Disposable cache, durable record. The only non-committed state (.trie/) can be deleted and rebuilt from source at any time.

The working context layer for coding agents.

trie setup wires the indexes into opencode, Claude Code, Cursor, and friends: reading tools resolve questions in prose, and the intent gate makes agents explain their own changes.

grep that sees symbols

Searches the symbol graph, not bytes. Every hit returns a qname, signature, one-liner, and centrality — “is this the right function?” is answered in the result row, not by opening the file.

read that returns context

Reading a symbol returns its prose plus one-liners for every caller and callee. --history appends the intent trail. A dozen speculative file reads become two or three round-trips of prose.

trace that walks the graph

Blast radius before a change, execution paths between two symbols, entry-point discovery — structural questions answered structurally.

And on the write side: agents record their intent notes through the same gate humans use. The context the next session reads is guaranteed to include why this one did what it did — the loop closes.

trie is built this way. Every commit in its own repository passes the gate it ships; its triefacts/ tree is generated and enforced by itself.
